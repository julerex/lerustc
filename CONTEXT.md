# Lerustc

A build harness and patch set that produces dependency-minimized Rust compiler toolchains. It began with fully static Linux x86_64 distributions (embedded Cranelift, multicall Wild linker, musl for the host compiler) and is being extended to cross-compile to DirectRedox targets.

## Language

**DirectRedox**:
A Rust target environment for Redox OS in which the standard library and user programs perform all operating-system interactions exclusively via the Redox kernel's native system calls and scheme interface. There is no relibc, no C standard library, no musl, and no POSIX layer.

_Avoid_: redox (overloaded with the OS itself and the existing RelibcRedox targets), raw-redox, bare-redox, syscall-redox, no-libc-redox.

**RelibcRedox**:
The pre-existing upstream targets (`x86_64-unknown-redox` and friends) that are defined with `env = "relibc"` and depend on the relibc project for their C library and POSIX-compatible surface.

_Avoid_: standard-redox, the-redox-target.

**CrossDirectRedox**:
The initial supported usage mode: a Linux-hosted lerustc (the current static-musl artifact or its evolution) is used as a cross-compiler to produce DirectRedox executables and the corresponding std rlibs that go into the sysroot.

**NativeDirectRedoxRustc**:
A `rustc` binary that executes as a Redox process under DirectRedox rules. Explicitly out of scope for the first phase of work; the project is starting with the cross-compiler case.

**MulticallLinker**:
The technique (already used for Wild on Linux) in which the single rustc binary, when invoked with a special environment variable or argv[0], dispatches to an embedded linker implementation instead of the normal driver. This eliminates the need for an external `ld`.

**BuiltinCodegen**:
A codegen backend (currently Cranelift) that is compiled into the rustc binary as a static rlib and registered directly, rather than loaded as a separate dylib from the sysroot.

**DirectRedoxTarget**:
A first-class built-in target triple (e.g. `x86_64-unknown-redox-direct`) added via a dedicated spec file under `compiler/rustc_target/src/spec/targets/`, registered in the static list in `spec/mod.rs`, using `os = "redox"` + the new `env = "direct"` (with `Env::Direct` variant). These targets deliberately differ from the RelibcRedox triples to keep the two environments separate and first-class inside the compiler. Custom target JSONs are not used as the primary mechanism.

**DirectRedoxPal**:
The dedicated platform abstraction layer implementation (library/std/src/sys/pal/redox/) that supplies all std sys interfaces (I/O, env, threads stubs, etc.) by calling directly into the redox_syscall crate and Redox's native scheme interface. It is completely separate from the `unix/` pal used by RelibcRedox.

**DirectRedoxRuntimeEntry**:
The no_mangle C-compatible entry symbol (conventionally named `runtime_entry`, following the hermit pattern) provided by the DirectRedoxPal. The Redox kernel (or exec mechanism) transfers control to it; it performs minimal scheme/argument/environment bootstrap, invokes std runtime init, and transfers to user `main` (or lang_start). No relibc crt0 or POSIX startup code is used.

**MinimalDirectStdSurface**:
The deliberately limited but immediately useful subset of std committed for the initial CrossDirectRedox sysroot: core alloc + panic, scheme-based stdio and fs (via paths like "file:...", "debug:"), env/args, and basic I/O traits so that `println!` and simple `std::fs` work. Threads, process spawning, and most `std::os::redox` extensions are out of scope for the first iteration.

**DirectRedoxLinkage**:
The linkage and startup model for all DirectRedox executables: fully static ELF, self-contained (no external crt objects or relibc), entry via the DirectRedoxRuntimeEntry symbol (no_mangle runtime_entry following the hermit convention), with the target spec declaring no pre/post CRT objects, crt-static, and a self-contained LLD (rust-lld) as linker. The MulticallLinker technique (Wild) is not used for these produced binaries; it remains specific to the Linux host compiler.

**CrossDirectRedoxBuild**:
The additional build phase (executed after the static Linux-multicall host rustc is ready) that uses the host compiler to cross-build the standard library (and supporting crates) for DirectRedox targets and installs the resulting rlibs into the sysroot under lib/rustlib/<triple>/. This enables the primary Linux rustc artifact to function as a cross-compiler without changing how the compiler binary itself is built or linked.

**DirectRedoxSysroot**:
The portion of a lerustc distribution containing the pre-built rlibs for one or more DirectRedox targets. It is generated by CrossDirectRedoxBuild and consumed by the Linux-hosted rustc when `--target <direct-triple> --sysroot <dist>` is used.

**CrossSmoke**:
The optional verification path in the test harness (modeled on the existing container smoke in smoke.sh) that, when DirectRedox rlibs are present, compiles a small program exercising the MinimalDirectStdSurface for a DirectRedoxTarget and, if a Redox runner such as redoxer (or QEMU-based environment) is available, executes the resulting SchemeNativeBinary inside a Redox VM to validate the DirectRedoxPal, DirectRedoxRuntimeEntry, and DirectRedoxLinkage. When no runner is present, the binary is still successfully compiled and a note is emitted. The primary smoke path remains exclusively focused on the Linux-hosted multicall rustc artifact.
